  • 答案默认锁着，需要点两次才展开。看过答案的题会在目录里标成 ○，第二天回来重做。
  • 这个页面不联网、不调用任何模型。练的时候不要开另一个窗口问 AI——那一轮面试你没有。

写给面试官看的四个信号

类型注解

签名上写 def f(rows: list[dict], limit: int = 10) -> dict[str, int]:。三秒钟的事，直接把代码从"脚本"抬到"生产代码"。

依赖注入

时钟、sleep、HTTP 客户端做成构造参数。说一句"这样能测"，比写十行测试更有效。

边界情况先说

动手前口述："空输入、重复键、超长单条、时间戳乱序——我先按这四个来。" 面试官会点头。

明确取舍

"我这里跳过坏行并收集起来，因为这是批处理。如果是转账我会反过来。" 这一句是 FDE 和 SWE 的分界线。

FDE 的一轮 45 分钟怎么分

0-3   min  澄清。问数据规模、问输入格式、问谁用、问失败了会怎样。
           把假设写成注释放在文件顶部。
3-8   min  写签名和数据结构，口述你打算怎么做。不要沉默地敲。
8-30  min  实现。先跑通最朴素的版本，再优化。
           每写完一块就说一句这块在干什么。
30-40 min  自己找边界：空输入、重复、超长、乱序。当场加测试。
40-45 min  说出你没做的部分和为什么。"如果给我多一小时，我会加 X。"
最常见的死法不是写不出来，是沉默地写。面试官打不出分。哪怕卡住了也要说："我在想用 dict 还是 heap，dict 更简单我先用 dict。"

这个岗位的编码轮和 LeetCode 不一样

  • 题目通常分阶段追加需求，逼你重构前面写的代码。第一阶段的可扩展性比速度重要。
  • 数据是脏的：缺字段、类型混乱、编码乱、时间戳乱序。处理脏数据的判断力就是分数。
  • 还有一轮模糊案例题：客户扔一个含糊的问题，你要拆成方案。这一轮权重最高、通过率最低，而且不写代码。
  • 所以别把全部时间投在刷算法题上。把 Python 练到"不用查文档就能流畅写"，然后去练拆解和沟通。

面试当天的三条

  • 先把函数签名和 return 的形状写出来，再填中间。这样任何时候被打断都有能跑的东西。
  • 不确定库函数的确切名字就说出来："这里我要一个稳定排序，标准库里应该是 sorted，我先这么写。" 面试官通常会直接告诉你。
  • 最后五分钟留给自我批评。主动说出你代码里的弱点，比让面试官发现好得多。
